## 3. Root Cause
BUG-002: Original one-liner:
  const r = await getOne('receipts', id) || await fsGetOneSafe('receipts', id);

getOne() is an IndexedDB Promise that REJECTS on IDB error (r.onerror = () => rej(r.error)).
When that rejection propagates as an uncaught exception, the || to fsGetOneSafe NEVER RUNS.
Also: order was wrong — IndexedDB-first contradicts Firestore-authoritative architecture.

## 4. Fix
Replaced with Firestore-first + IDB safe-fallback pattern:
  - Firestore (fsGetOneSafe) tried FIRST in try/catch
  - IDB (getOne) tried SECOND in separate try/catch — any IDB error is caught+logged, never propagates
  - Not-found: alert('Receipt not found. It may have been deleted or the ID is invalid.')
  - ZERO write operations
